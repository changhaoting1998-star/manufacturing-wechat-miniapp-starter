# Contributing

1. Keep examples synthetic and organization-neutral.
2. Add tests for authorization, idempotency, failure behavior, and receipts.
3. Never commit credentials, production identifiers, employee data, payroll data, signatures, locations, databases, exports, or preview codes.
4. Run `npm test` and `npm run demo` before opening a pull request.
5. Explain any new data field, its purpose, retention needs, and whether it is returned to the Mini Program client.
